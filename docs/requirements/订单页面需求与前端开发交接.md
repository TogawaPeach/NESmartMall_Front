用户已确认先完成订单前端，先写 Require 再实施。沿用 Vue 3、TypeScript、Element Plus、商城导航和现有账号会话；用开发模拟打通订单列表及详情。订单展示已提交的交易，购物车结算、创建订单和支付流程不在本期范围。

## 2. 页面与入口

- 已登录点击顶部「我的订单」在当前标签页进入 `/orders`，路由名 `orders`。购物车原有新标签页行为保持现有实现。
- 未登录点击入口打开现有登录弹窗；成功登录后进入订单列表，取消则停留原页。
- `/orders/:orderNo` 为订单详情，路由名 `order-detail`。查看详情在当前标签页跳转，返回列表保留状态筛选。
- 直接进入列表或详情而没有有效会话时显示登录引导，不发送订单查询；登录后自动加载当前页面。
- 退出、过期、其他标签页换账号时立即清除旧订单并重载或回到登录引导；迟到响应不能覆盖新账户或新页面。

## 3. 订单列表

- 标题「我的订单」，状态筛选：全部、待付款、待发货、待收货、已完成、已取消。
- 状态保存为 `/orders?status=PENDING_PAYMENT`；全部省略 status，非法状态回全部。一次查询并展示当前用户在所选状态下的全部订单，不分页；保留后端排序，默认最新在前。旧链接中的 page 参数忽略，详情往返不再传递页码。
- 订单卡片展示下单时间、订单号、状态、商品快照（图片、名称、型号、成交单价、数量）、订单金额（payableAmountFen）及「查看详情」。金额单位为人民币分，以整数计算并复用金额格式化函数。
- 待付款展示禁用的「去付款」「取消订单」，待收货展示禁用的「确认收货」。页面说明交易操作暂未开放，不能假装付款或改变真实订单状态。
- 支持骨架加载、真实空列表、筛选无结果、无权限、服务未开放、加载失败及重试；响应异常不能转换为空列表。
- 不添加订单搜索、退款售后、发票或批量操作；后续独立确认。

## 4. 订单详情

- 顶部展示订单状态、订单号和对应说明；进度包含提交订单、支付成功、商家发货、交易完成，已取消单独表达，不误标为完成。
- 展示下单、付款、发货、完成/取消时间（按状态适用）；没有发生的事件显示「待完成」。
- 收货信息：收货人、脱敏手机号、地址；前端在适配层对原始号码兜底脱敏，已脱敏号码保留，无法有效脱敏的短号显示「已隐藏」；物流信息只展示运单号，不要求承运商，无信息显示「暂无物流信息」。模拟信息明确为虚构。
- 商品和价格使用下单快照，不能用当前商品接口价格替换成交信息，不能因商品下架丢失历史名称。
- 展示商品金额、运费、优惠、应付金额、实付金额。未付款实付为 null 并显示「尚未付款」，0 元与未付款区分。
- 不存在或当前用户不可见的订单显示「订单不存在或无法访问」，不泄漏其他用户数据；提供返回订单列表入口。

## 5. 查询接口草案

所有请求复用 `src/api/http.ts` 的 Bearer 处理。只请求网关 `/api`，不传 userId、accountId、token 查询参数或内部身份头。商品明细 id 和 productId 为正整数十进制字符串，避免大整数精度丢失；订单主表 id 不对外返回。对外订单号 orderNo 始终按字符串传递，格式沿用订单表设计的 JW 前缀加雪花 ID 十进制数字，总长不超过 64；详情请求不使用内部 id，不把订单号转成 Number。

列表：`GET /api/orders`；按状态筛选时使用 `GET /api/orders?status=PENDING_PAYMENT`。不发送 pageNum、pageSize 或 limit；始终携带有效的 `Authorization: Bearer <token>`。后端必须从可信登录上下文获取当前用户，限定 user_id 后一次查询全部匹配订单，按 created_at DESC、id DESC 排序；不得启用分页或默认截断。

```json
{
  "code": 200,
  "message": "OK",
  "data": []
}
```

列表 data 为 OrderSummary 数组，每个元素只要求以下字段，items 保存该笔订单的商品快照；不要求或补造 paidAt、paidAmountFen、recipient、logistics 及其他详情字段。卡片只使用 payableAmountFen 展示“订单金额”，不能将其标成“实付金额”。

```json
{
  "orderNo": "JW1980123456789012300",
  "status": "PENDING_PAYMENT",
  "createdAt": "2026-10-17T01:00:00Z",
  "payableAmountFen": 990,
  "items": [{
    "id": "1", "productId": "1", "name": "GNSS 定位模块",
    "model": "DX-GP21", "coverUrl": null, "unitPriceFen": 990, "quantity": 1
  }]
}
```

列表仍严格校验上述必填字段、商品条目、状态、订单号唯一性、商品明细 ID 唯一性、日期与金额安全整数范围，商品行小计合计不可溢出。列表不包含运费、优惠等金额明细，不能要求 payableAmountFen 必须等于商品小计。旧包装、null、缺失列表必填字段均为响应错误。后端顺序、状态筛选、Bearer 和会话隔离保留。

详情：`GET /api/orders/{orderNo}`，orderNo 来自列表订单对象，路径参数不是内部 id；例如 `GET /api/orders/JW1980123456789012300`。成功 data 为下面的完整单订单对象，响应 orderNo 必须与请求值完全一致；该完整结构只用于详情校验。详情真实后端尚未实现，本次不修改详情字段或放松校验。

```json
{
  "orderNo": "JW202610160001",
  "status": "PENDING_PAYMENT",
  "createdAt": "2026-10-16T02:00:00Z",
  "paidAt": null,
  "shippedAt": null,
  "completedAt": null,
  "cancelledAt": null,
  "items": [{
    "id": "101", "productId": "42", "name": "GNSS 接收机",
    "model": "RTK-01", "coverUrl": null, "unitPriceFen": 129900, "quantity": 1
  }],
  "goodsAmountFen": 129900,
  "shippingFeeFen": 0,
  "discountAmountFen": 0,
  "payableAmountFen": 129900,
  "paidAmountFen": null,
  "recipient": { "name": "演示收货人", "phone": "138****0000", "address": "演示地址（虚构）" },
  "logistics": null
}
```

- status 枚举：`PENDING_PAYMENT`、`PENDING_SHIPMENT`、`PENDING_RECEIPT`、`COMPLETED`、`CANCELLED`。
- logistics 非空时为 `{ "trackingNo": "运单号" }`，不要求 carrier；该调整待后续前端适配。
- 列表及详情金额为非负安全整数分，数量为正安全整数；行小计和汇总不能溢出。详情的商品金额等于快照小计合计；当前无订单级优惠，discountAmountFen 固定返回 0，应付等于商品金额 + 运费。
- 每笔订单至少一个商品，ID 不重复；时间采用有效日历日期的带时区 ISO 8601，页面统一以 Asia/Shanghai 显示。拒绝 2 月 30 日等会被 Date 自动归一化的日期。
- 详情的进度事件须符合状态：待付款不能带支付/发货/完成事件；待发货不能带发货/完成事件；待收货不能带完成事件；仅已取消允许取消时间，取消单不能带发货/完成事件。付款时间和实付金额必须同时存在或同时为空，事件时间不早于前一事件。
- 图片只允许 HTTP(S) URL 或 null；缺失/失败显示占位。未知状态、字段缺失、错误金额和非法时间显示响应错误，不捏造默认订单。
- 列表成功响应为 `Result<OrderVO[]>`，data 必须是数组；不接收或返回分页字段，不返回 list/total 包装。空结果为 data: []，订单数量由 data.length 得到；每笔订单的商品条目数为 items.length，与订单数区分。后端仍须全量返回，不能默认截断；省去 total 后前端不能仅凭响应检测是否漏单，应在联调时用超过 5 笔订单的数据核对。旧包装对象、null、字段缺失及其他非法响应应提示错误，不能当作空数组，也不自动兼容旧包装。
- HTTP 或业务 401 显示登录引导；403 无权限；列表 404/503 表示服务未开放，详情 404 表示不存在或不可见；其他错误支持重试。统一 HTTP 层继续负责当前 token 的 401 清理。
- 后端须以认证用户约束列表及详情查询；不能因猜到订单号查看其他账户。订单列表按现有总需求不引入 Redis 缓存。
