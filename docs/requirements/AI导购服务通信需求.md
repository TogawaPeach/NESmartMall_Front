## 1. 当前状态与服务职责

前端目前只有标注“AI 导购 · 暂未开放”的入口；后端尚无 AI 接口、Python 服务、模型调用或知识库。本文不表示 AI 功能已经可用。

| 部分 | 建议职责 |
| --- | --- |
| 网关 | 浏览器统一入口、JWT 校验、路由与访问限制；AI 的长连接参数单独设计 |
| Java 导购业务入口 | 验证用户与会话权限，组织允许访问的商品数据，调用 Python，校验推荐商品并向前端返回结果 |
| 商品等 Java 业务服务 | 管理商品、价格、状态及其他权威业务事实，执行接口与数据权限 |
| Python AI 服务 | 模型调用、推荐推理与解释；按后续设计支持检索或工具调用 |
| Nacos | 注册和发现 Python 实例，供 Java 按服务名调用 |

Java 导购业务入口的模块归属尚待确定，不把 AI 推理或导购业务加入认证服务。Python 框架建议 FastAPI，服务名建议 mall-ai-service；这些名称和框架属于草案。

默认建议链路：浏览器 → 网关 → Java 导购业务入口 → Python AI 服务 → Java 校验结果 → 网关 → 浏览器。

如果后续确认没有 Java 编排需求，也可以由网关直接路由 Python，但 Python 仍需遵循统一令牌处理约定并检查用户范围和业务权限；当前仅解码方案存在上述身份伪造缺口；采用这种链路前同步路由、鉴权与错误契约。

## 2. 普通同步调用：HTTP + JSON

Java 通过已选的 OpenFeign + Apache HttpClient 5（HC5）调用 Python 的 REST API。Python 接收 JSON 并返回 JSON，双方约定字段、类型、状态码和 API 版本，不依赖 Java 对象或 Python 对象在进程间直接共享。

Python 实例纳入 Nacos 注册发现。使用兼容的 Python SDK 或受支持注册方式，核对注册、健康、续租或连接生命周期、下线行为；Java 通过 Spring Cloud LoadBalancer 按服务名选择实例。必须验证 Java 能实际发现 Python 实例，且登记的地址从 Java 部署环境可达。[Nacos 官方 Python SDK](https://github.com/nacos-group/nacos-sdk-python)

| 接口 | 所在位置 | 用途与状态 |
| --- | --- | --- |
| POST /api/ai/recommendations | Java 对外业务入口，经网关访问 | 整段返回商品推荐及解释；接口草案 |
| POST /internal/ai/recommendations | Python 内部 HTTP API | 接收用户需求与允许访问的商品上下文，返回推理结果；接口草案 |

请求草案包含 requestId、用户需求、可选 conversationId、筛选条件及商品上下文。用户和会话归属由已验证身份取得，不能信任请求体中的 userId 或 merchantId。

Java 可先取得允许推荐的商品，再把必要字段传给 Python；如果后续采用检索或工具调用，Python 通过受保护 Java API 获取允许的数据，不直接访问或修改商品、账号或订单业务表。价格仍遵守项目的整数分约定，ID 建议按字符串传递。

Python 返回推荐商品 ID 和解释等结构化数据。Java 在对外返回前核对商品存在、状态、真实价格、用户可访问范围及详情关联；AI 生成的商品 ID、价格或链接不能直接成为权威业务事实。模型接收必要业务上下文，不接收用于鉴权的 JWT、密码或服务凭据。

普通 JSON 接口继续使用 Result。Python 内部响应结构与 Java 的错误映射随接口契约定案；对外成功包含真实可用商品，正常没有符合条件的商品时可以返回成功空列表与说明。超时或调用失败返回明确错误，不伪装为无推荐商品。

## 3. 可选流式调用：HTTP SSE

如果后期要求回答逐段或逐字展示，建议独立使用 SSE，响应类型为 text/event-stream。是否需要在首期提供流式回答尚未确认；完整推荐 JSON 与流式聊天接口分别约定。[FastAPI SSE 文档](https://fastapi.tiangolo.com/tutorial/server-sent-events/)

建议对外流式路径为 POST /api/ai/chat/stream，Java 持续读取 Python 流并逐块转发。普通 Feign DTO 返回方式不能视为已经支持流式转发；可以在现有 MVC 技术栈中使用支持流式读取的客户端，例如 WebClient，再通过 MVC 的 SSE 支持向前端输出。具体客户端、连接池与服务发现方式单独验收，不假定自动复用 Feign 的 HC5 配置。[Spring WebClient](https://docs.spring.io/spring-framework/reference/web/webflux-webclient.html)、[Spring MVC 异步响应](https://docs.spring.io/spring-framework/reference/web/webmvc/mvc-ann-async.html)

流式事件建议包含 delta、done、error，以及 requestId、会话标识和必要的事件顺序信息；字段与恢复语义待细化。开启流之前的鉴权或参数错误仍使用 HTTP 状态和 Result，开启流之后的失败通过约定的 error 事件或断流处理，不能承诺已发送响应头后还能改为新的 HTTP 错误状态。

SSE 成功响应是事件流，不把整条连接包装为单个 Result JSON。此项为现有普通业务响应约定的流式扩展，各事件的数据格式按 AI 协议明确。

前端仍需携带 Bearer JWT。建议通过支持请求头的 fetch 读取 SSE；原生 EventSource 不能任意设置 Authorization 请求头，不把长期 JWT 拼入 URL。页面关闭、用户停止或请求中断时，取消上下游任务并释放连接，停止无意义的继续生成。

网关、反向代理、Java 与 Python 分别明确首响应、空闲、整体截止时间、心跳、缓冲和并发连接限制，验证事件逐块到达，避免被代理缓冲成一次返回。当前普通 Axios 请求超时为 10 秒，AI 请求需独立设计，不直接改变所有商品接口超时。

## 4. 后期异步任务：RabbitMQ

知识库索引构建、批量商品内容处理或离线推荐等后台任务，可使用已选的 RabbitMQ。是否建设这些 AI 任务尚未确认，不能把全部实时对话默认改成消息队列请求。

Java 提交带 taskId 的任务，Python 消费并在自己的执行范围内处理，再通过结果事件或状态接口供 Java 查询；前端通过网关获取任务状态。任务归属、超时、取消、失败、幂等与有限重试遵守已有消息可靠性要求，不把重复生成当作无成本操作。

Python 消费任务和结果处理不成为原 Java 请求的同一个 Seata 分布式事务分支。消息确认、重试与业务完成语义分别定义。

## 5. 业务权限、状态与事务边界

- 普通调用、流式调用及任务状态查询都需验证身份和会话或任务归属，不能通过猜测 conversationId、requestId 或 taskId 访问其他用户内容。
- Java 到 Python 的服务身份、用户上下文与受众范围需明确；Python 不信任任意客户端身份头，不能只依赖内部网络授权。
- 商品数据以 Java 业务服务为准。Python 负责推荐，不因一次模型输出就修改商品或创建订单；未来实际业务写入继续通过受保护 Java 接口执行原有权限、校验和幂等约束。
- 模型推理、聊天、商品查询和等待模型输出不进入 Seata 全局事务，也不在长时间数据库事务中等待模型完成。
- Redis 可以按后续设计缓存商品上下文等读取数据；会话保存位置、个性化回答是否缓存、用户隔离与保留时间尚未确定。Redis 缓存不能替代权限检查或权威商品状态。
- 模型供应方、密钥、提示组织、检索、调用限制和成本上限在 Python 服务设计时明确；本次不选择具体模型供应方。

## 6. 待执行验收

| 场景 | 预期结果 |
| --- | --- |
| Java 调用 Python | HTTP JSON 契约一致，实际使用 OpenFeign + HC5，能按 Nacos 服务名发现实例 |
| 推荐实际商品 | 结果关联真实可访问商品，价格和详情路径由业务数据核对 |
| 无效身份或他人会话/任务 | 拒绝访问，不信任客户端伪造身份与归属 |
| Python 不可用或模型超时 | 返回可区分的失败，前端显示导购暂不可用，不影响独立商品浏览接口 |
| 实时流，若启用 | 持续分段输出；鉴权失败发生在开启流前；流内错误按协议处理 |
| 用户停止或断连 | 上下游取消与连接释放生效，不持续积压任务 |
| 异步任务，若启用 | 状态与结果可查询，重复投递幂等，失败有限重试并可追踪 |
| AI 与事务 | 模型等待不占用业务事务；业务写入仍由 Java 权限与事务控制 |
