## 1. 当前代码与保留约定

- auth 已有 AuthController、LoginDTO、Account、AccountMapper/XML、AuthServiceImpl、JwtUtil、LoginVO、GlobalExceptionHandler；完成账号密码/状态检查和 JWT 签发，尚未完整统一 JSON 异常。
- gateway 当前是 MVC 静态路由，尚无 JwtDecoder、权限过滤或可信身份转发。
- product 已有首页/分类、PageHelper 分页和 keyword 查询；尚无用户上下文、merchant_id 或商家 API。
- 前端已有 localStorage、刷新恢复、自动 Bearer、当前令牌匹配的 401 清理；商家导航和 403 专用提示尚待开发。
- 保留账户单角色 0 商家/1 用户、商家 ID=account.id、nickname 即店铺名、BCrypt、同库、Result、登录响应及一天 TTL，详见 [账户与登录最终约定](./账户与登录最终约定.md)。

## 2. 服务职责和链路

登录：前端 → gateway → auth 验账号密码与状态、读取数据库角色 → JWT 返回。

受保护：前端 Bearer → gateway 本地验签与入口角色 → 覆盖 user-info/user-role 并附加内部服务凭据 → product 验调用来源、建立 CurrentUser/ThreadLocal → 接口权限/归属 → 执行业务 → 清理上下文。

auth 不接收所有业务请求来统一判权，不建设 /internal/auth/verify。product 不复制 JWT 验签器；其角色和资源权限仍在自身业务层保障。auth 停止只影响登录/账户接口，不阻塞已有有效令牌访问正常 product。

## 3. 公开与保护规则

| 方法与路径 | 规则 |
| --- | --- |
| POST /api/auth/login | 公开，不强制验证旧 token |
| GET /api/products | 公开，分类前八；product 强制最多八条 |
| GET /api/products/page | 须登录，keyword 查询也受保护 |
| /api/merchant/** | 须登录且 MERCHANT；product 判商品归属 |
| 后续订单/购物车、GET /api/auth/me | 须登录，尚未全部设计或实现 |
| OPTIONS | 按 CORS 策略处理预检，不执行业务 |

精确方法/路径匹配，不公开整个 products/auth 通配路径；未知入口默认保护。公开链路须跳过 Bearer 验证，不能仅 permitAll 后仍因旧 token 失败。全部路径先清理客户端身份头，再决定白名单。

## 4. JWT 校验与首期状态窗口

HS256 验签密钥=SHA-256(UTF-8 配置文本)，与 auth 一致；iss=NESmartMall，aud 包含 nesmartmall-api，sub 正 Long 的十进制字符串，roles 为单个 MERCHANT/CUSTOMER，iat/exp 必需且时间合法，存在 nbf 时也校验。角色转换到 Spring 权限名称时使用 ROLE_ 前缀。

首期离线验证，不查询账户当前状态；登录时禁用不得签发，登录后禁用/删除/改角色不即时撤销已有 JWT，最长约一天。退出清前端不撤销服务端令牌。明确边界见跨 Harness 文档，不能沿用旧集中方案的即时账户检查验收。

## 5. 内部身份与错误

内部头约定 user-info、user-role；首期建议按目标服务配置独立 X-Service-Token，由接收服务在解析身份前验证。外部同名头全部清除，缺内部凭据不得进入业务；正式部署限制服务端口并采用安全传输。MVC 身份配置显式装配到业务服务，不能用 DispatcherServlet 存在性排除 MVC gateway。

| 情况 | HTTP / Result.code |
| --- | --- |
| 登录参数/JSON 错误 | 400 / 400 |
| 密码错误、登录账户禁用；受保护请求 JWT 无效/缺失 | 401 / 401 |
| 角色不足或内部来源认证失败 | 403 / 403 |
| 商家操作他人资源 | 建议 404 / 404 |
| 目标服务不可用/超时/内部故障 | 明确 5xx，不伪装 401 |
