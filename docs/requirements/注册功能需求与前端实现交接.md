# 注册功能需求与前端实现交接

更新时间：2026-10-15
状态：用户已确认后端注册接口完成并提供返回 JWT 的成功响应；前端自动登录已实现，96/96 项自动化测试通过。本轮前端验证使用模拟响应，完整真实接口联调仍待验收；未修改 Java、网关或数据库。

## 1. 已确认的注册约定

- 账号就是手机号，字段名为 `account`；昵称为 `nickname`；请求中的原始密码字段为 `password`。
- 数据库继续使用 `password_hash` 保存后端 BCrypt 生成的密码哈希，不把请求字段改为 password_hash。
- 一个账号只有一个角色：用户 `role = 1`，商家 `role = 0`；注册表单默认选择用户，允许用户选择商家直接注册。此条替代此前“普通注册由后端固定赋予 1，商家创建方式待定”的约定。
- 商家昵称继续作为店铺名；商家 ID 继续复用账户 ID。
- 表中已有 `status`，默认值为 `1`；前端不传该字段，本轮不改表或默认值。
- 注册成功即自动登录：auth 创建账户后复用现有 JwtUtil 签发 JWT，返回与登录相同结构的 LoginVO；前端保存会话并关闭弹窗。此条替代此前“注册成功返回登录、不签发 JWT”的约定。

## 2. 页面行为（前端已实现）

- 现有登录按钮下方增加全宽空心“注册”按钮，与实心登录按钮区分。
- 点击后在同一个弹窗切换为“注册经纬智选”，包含手机号账号、昵称、密码和账户类型单选组（用户 / 商家）。注册表单提供“返回登录”。
- 切换时保留账号，清空密码、昵称和提示，角色恢复默认用户；不因切换校验规则立即显示所有必填错误。
- 提交前校验手机号符合 `^1[3-9]\d{9}$`；昵称去除首尾空白后为 1 至 64 个字符；密码不能全为空白；role 必须是数字 0 或 1。登录表单继续兼容既有非手机号账号，不新增手机号限制。
- 等待响应期间禁用字段和操作按钮，显示“正在注册…”，防止重复提交。关闭或卸载弹窗取消请求并清空表单；已取消的响应不得更新重新打开的弹窗。
- 成功后校验完整登录响应，复用现有登录会话逻辑保存 accessToken、tokenType、expiresAt 和 user，关闭弹窗并清空表单；停留当前页面，沿用已有登录成功后的行为，不返回登录表单，不另发一次登录请求。刷新、跨标签共享及到期处理与登录一致。当前商品列表页会自动继续加载原查询，并携带新令牌。
- 登录与注册弹窗均不显示底部说明小字；未登录的顶部用户图标悬浮提示及无障碍名称仅为“登录”。
- 失败优先显示后端 message，保留账号、昵称和角色，清空密码；可重新提交。网络断开及超时显示对应提示。

## 3. 请求与成功响应

```http
POST /api/auth/register
Content-Type: application/json
Accept: application/json
```

```json
{
  "account": "13800138000",
  "nickname": "测绘小助手",
  "password": "ExamplePass123!",
  "role": 1
}
```

示例手机号及密码仅用于说明字段，不是真实账号。请求 body 仅包含以上四项；account、nickname 去除首尾空白，password 原样提交，role 使用数字。前端不发送 status、账户 ID、时间或密码哈希。

成功约定为 HTTP 200，Result.code 使用数字 200：

```json
{
  "code": 200,
  "message": "注册成功",
  "data": {
    "accessToken": "签名后的JWT字符串",
    "tokenType": "Bearer",
    "expiresIn": 86400,
    "user": {
      "id": "10001",
      "account": "13800138000",
      "nickname": "测绘小助手",
      "role": 1
    }
  }
}
```

data 复用登录接口的 LoginVO。前端必须同时检查严格的 `code === 200` 及完整有效的登录数据，不能仅凭 code 建立会话；缺少令牌或用户信息时按响应异常处理。expiresIn 单位为秒，取实际配置值，示例 86400 不由前端硬编码；user.id 使用数据库生成的账户 ID 并转为字符串。后续手动登录仍走原有 `/api/auth/login`。

参数不合法返回 HTTP 400，手机号重复建议返回 HTTP 409，均使用同码 `code`、可展示的 `message` 和 `data: null`。后端不能仅依赖前端校验。

## 4. 后端对接约定与待验收项

用户已确认注册接口完成；以下为需对照后端实现验收的约定，不表示本轮前端已逐项验证。

1. auth 新增注册 DTO、Controller、Service 和账户写入：只接收 account、nickname、password、role，校验必填、手机号、昵称及角色范围。原始密码保持不变；考虑现有 BCrypt 编码器限制，UTF-8 编码超过 72 字节时返回明确 HTTP 400，禁止静默截断。
2. account 建立/保留唯一约束，手机号重复（包括并发插入冲突）返回明确的 409 Result；昵称不用于登录唯一性。
3. BCrypt 处理原始 password 后写入 password_hash；status 保持现有默认 1，ID 和时间由后端/数据库生成。不返回密码或密码哈希。
4. gateway 的公开白名单精确增加 `POST /api/auth/register`；匿名可访问，附带旧 token 时也跳过验签，不整体开放 `/api/auth/**`。
5. 注册 Service 返回 LoginVO；成功写入后取得数据库生成的 ID，使用新建账户的真实角色和已有 JwtUtil 签发 JWT，返回新建账户实际写入的昵称及角色。使用本地事务保证写入和签发流程失败时回滚，不在写入前签发，不再次调用登录接口，不返回或保存明文密码/JWT 到 account 表。
6. 完成真实接口联调：两种角色注册并自动登录、正确账户 ID/昵称/角色及 JWT 声明、重复手机号（含并发）、非法字段、网关匿名及旧 token 放行、签发失败回滚，以及注册后后续请求携带令牌访问受保护接口。
