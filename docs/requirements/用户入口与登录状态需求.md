## 1. 用户入口

- 未登录时顶部用户图标的悬浮提示及无障碍名称仅为“登录”。点击顶部用户图标，在当前页面打开“登录经纬智选”弹窗，不打开新网页或标签页。
- 登录与注册弹窗均不显示底部说明小字。弹窗含账号、密码、密码可见切换及登录按钮，打开后焦点落在账号输入框。支持表单提交、关闭按钮和 Esc 关闭；关闭后焦点回到用户入口，点击遮罩不关闭。
- 必填项缺失时显示字段提示，不发请求。账号去除首尾空白，密码按用户输入原样提交，不限制账号为手机号。
- 等待登录时禁用输入和提交，显示“正在登录…”，防止重复请求。关闭弹窗取消进行中的登录并清空账号密码及错误；取消或迟到的结果不恢复已退出会话。
- 普通用户成功后关闭弹窗，保留原页面、URL、分类、搜索词与浏览位置；商家成功后进入 `/merchant/products`。若当前在受保护的商品列表页，登录或注册成功后自动继续加载原查询。
- 当前没有头像，继续使用 User 图标；桌面显示昵称，昵称为空时显示账号，窄屏保留图标，入口无障碍名称包含昵称。
- 已登录时点击入口打开账号菜单，展示昵称、账号及“退出登录”。已支持切换注册表单；商家账号菜单提供“商家工作台”，普通用户不展示。个人中心、找回密码未开发。

## 2. 登录请求

```http
POST /api/auth/login
Content-Type: application/json
Accept: application/json
```

```json
{
  "account": "示例账号",
  "password": "用户输入的密码"
}
```

开发浏览器请求使用相对路径 `/api/auth/login`，由 Vite 的 `/api` 代理转发到 `http://localhost:8080/api/auth/login`。部署时使用同源 `/api` 路由或 `VITE_API_BASE_URL`。请求 body 仅有 account、password，不发送角色、账户 ID。当前会话有未过期 token 时，由共享请求层统一附加 Bearer token；匿名或已过期时不附加。请求超时沿用共享 Axios 的 10 秒。

## 3. 登录响应

HTTP 200，成功业务响应：

```json
{
  "code": 200,
  "message": "OK",
  "data": {
    "accessToken": "后端返回的JWT字符串",
    "tokenType": "Bearer",
    "expiresIn": 86400,
    "user": {
      "id": "2",
      "account": "示例账号",
      "nickname": "user",
      "role": 1
    }
  }
}
```

- 只有 `code === 200` 且令牌及用户字段结构完整时建立会话；HTTP 200 不代表业务必然成功。
- accessToken 为非空且不含空白的字符串，tokenType 为 Bearer，expiresIn 为有效正数（单位秒），user.id 为字符串，account 和 nickname 为字符串，role 为整数。
- 本次实际响应的 expiresIn 为 86400 秒（24 小时），前端按每次返回值计算过期，不硬编码 24 小时。
- 数据库角色仍为 0 商家、1 普通用户；当前保存该字段并用于商家前端导航及页面守卫，不能作为后端授权依据。
- 业务失败和 HTTP 错误优先展示后端 message；网络断开、超时和响应格式异常显示对应提示。失败不建立新会话并清空密码，允许再次输入提交。

## 4. 刷新与后续请求

当前会话保存在同源标签页共享的 `localStorage`，键为 `nesmartmall.auth`，字段仅包括：

| 字段 | 用途 |
| --- | --- |
| accessToken | 后续接口的 Bearer 令牌 |
| tokenType | 固定 Bearer |
| expiresAt | 登录成功时 `Date.now() + expiresIn × 1000` |
| user | 昵称与账号展示所需的 id、account、nickname、role |

密码、密码哈希与登录请求对象不持久化。刷新时先检查存储结构和 expiresAt，合法且尚未过期才恢复展示；无效 JSON、缺失字段或已过期会话会被清理。浏览器禁用存储时允许页面内存登录，但不能保证刷新后恢复。

刷新不重发账号密码，不请求 `/api/auth/login` 或 `/api/auth/me`。当前会话 token 未过期时，后续所有通过共享 `http` 实例发往本项目后端的 API（包括首页公开接口及登录）自动附加：

```http
Authorization: Bearer <accessToken>
```

不会把 token、密码或整个 user 放入 URL，不把 user 或 expiresIn 附加到业务 body。相对地址及本项目后端的绝对地址均适用，包括配置的 `VITE_API_BASE_URL`；按最终地址的来源和路径范围判断，第三方地址不携带会话令牌。页面刷新时加载的 HTML 本身不通过该 Axios 拦截器发送 token；真正的身份传递发生在后续 API 请求。

恢复前端登录展示不等于后端已经认可身份；后端按已有规则处理每次携带令牌的请求。当前前端不通过 me 查询最新昵称、禁用状态或角色。最新后端设计为 gateway 本地验签及入口角色检查；首期禁用/改角色不即时撤销已有 JWT，最长持续至一天到期，详见最终约定与 本地 Require 的《登录鉴权实现需求与跨Harness交接》；当前链路尚未实现。

## 5. 过期与退出

- 前端根据 expiresAt 安排到期清理，并在发送业务请求前再次检查时间。
- HTTP 401 或业务 `code: 401` 仅在失败请求携带的 Authorization 与当前会话匹配时清理会话；旧请求失败不清理已切换的新 token，会话仍有效时登录或注册请求失败不清理原会话。
- 清理后入口恢复未登录图标，用户点击重新打开登录框；不自动弹出，不自动续期或循环重试。
- 退出登录只清除本地会话和存储，不调用尚未提供的注销接口，不表示服务端撤销 token。
- 会话在同源标签页间共享；刷新、新标签页及关闭浏览器后重新打开均可恢复未过期会话。登录、退出、过期及匹配当前 token 的 401 清理同步到其他标签页；不延长令牌有效期。
- 403 专用权限页面、服务端刷新/撤销、账户禁用与角色变更后的即时生效策略仍待实现或确认。

## 本轮修订：跨标签页共享登录

本节及上文已更新条款优先于此前按标签页保存会话、登录不带令牌或公开接口可省略有效令牌的旧约定。

- 已登录时保留“查看全部”和首页搜索在新标签页打开的交互；新页面从同源共享的 localStorage 恢复未过期会话，API 仍由共享请求层统一携带 Bearer token。未登录时改为当前页登录引导，详见下节。
- 请求发送、401 处理及登录返回前读取最新共享会话，避免 storage 事件延迟导致旧请求清除其他标签页的新登录；旧过期定时器同样不得删除新会话。
- 首次升级迁移旧 sessionStorage 的有效会话并删除旧记录。共享状态修订标记只用于识别变更和阻止重复迁移，不保存身份；即使另一标签页快速登录再退出，也必须使此前的迟到登录失效，退出后不得被其他旧标签页的旧记录重新恢复。
- 浏览器存储不可用时允许当前页面内存登录，但无法保证跨标签页共享或刷新恢复。
- 登录失败的 401、HTTP 403、网络错误与 5xx 不清理会话；主动退出或另一标签页切换会话后，迟到的登录结果不得覆盖共享状态。
- 本次只修改前端会话存储和同步，不需要后端读取浏览器存储。网关公开接口跳过验签、受保护接口验证 token 和可信身份转发仍待实现。
