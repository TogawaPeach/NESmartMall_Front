# 用户入口与登录状态需求

更新时间：2026-10-14\
需求编号：007\
状态：前端已实现；普通用户真实登录、刷新恢复和退出已完成浏览器验证。

本文记录当前商城用户入口的实际交互和接口契约。账户角色和 JWT 后端处理沿用 [账户与登录最终约定.md](./账户与登录最终约定.md)，网关路由见 [登录服务与网关需求.md](./登录服务与网关需求.md)。本次不修改数据库或后端鉴权方式。

## 1. 用户入口

- 未登录时点击顶部用户图标，在当前页面打开“登录经纬智选”弹窗，不打开新网页或标签页。
- 弹窗含账号、密码、密码可见切换及登录按钮，打开后焦点落在账号输入框。支持表单提交、关闭按钮和 Esc 关闭；关闭后焦点回到用户入口，点击遮罩不关闭。
- 必填项缺失时显示字段提示，不发请求。账号去除首尾空白，密码按用户输入原样提交，不限制账号为手机号。
- 等待登录时禁用输入和提交，显示“正在登录…”，防止重复请求。关闭弹窗取消进行中的登录并清空账号密码及错误；取消或迟到的结果不恢复已退出会话。
- 成功后关闭弹窗，保留原页面、URL、分类、搜索词与浏览位置；不跳转个人中心，也不自动重新查询商品。
- 当前没有头像，继续使用 User 图标；桌面显示昵称，昵称为空时显示账号，窄屏保留图标，入口无障碍名称包含昵称。
- 已登录时点击入口打开账号菜单，展示昵称、账号及“退出登录”。未开发个人中心、注册、找回密码或商家后台导航。

## 2. 登录请求

```http
POST /api/auth/login
Content-Type: application/json
Accept: application/json
```

```json
{
  "account": "示例账号",
  "password": "用户输入的密码"
}
```

开发浏览器请求使用相对路径 `/api/auth/login`，由 Vite 的 `/api` 代理转发到 `http://localhost:8080/api/auth/login`。部署时使用同源 `/api` 路由或 `VITE_API_BASE_URL`。请求 body 仅有 account、password，不发送角色、账户 ID，也不自动附加旧 Bearer token。请求超时沿用共享 Axios 的 10 秒。

## 3. 登录响应

HTTP 200，成功业务响应：

```json
{
  "code": 200,
  "message": "OK",
  "data": {
    "accessToken": "后端返回的JWT字符串",
    "tokenType": "Bearer",
    "expiresIn": 86400,
    "user": {
      "id": "2",
      "account": "示例账号",
      "nickname": "user",
      "role": 1
    }
  }
}
```

- 只有 `code === 200` 且令牌及用户字段结构完整时建立会话；HTTP 200 不代表业务必然成功。
- accessToken 为非空且不含空白的字符串，tokenType 为 Bearer，expiresIn 为有效正数（单位秒），user.id 为字符串，account 和 nickname 为字符串，role 为整数。
- 本次实际响应的 expiresIn 为 86400 秒（24 小时），前端按每次返回值计算过期，不硬编码 24 小时。
- 数据库角色仍为 0 商家、1 普通用户；当前保存该字段，不据此实现商家跳转或后端授权。
- 业务失败和 HTTP 错误优先展示后端 message；网络断开、超时和响应格式异常显示对应提示。失败不建立新会话并清空密码，允许再次输入提交。

## 4. 刷新与后续请求

当前会话保存在本标签页 `sessionStorage`，键为 `nesmartmall.auth`，字段仅包括：

| 字段 | 用途 |
| --- | --- |
| accessToken | 后续接口的 Bearer 令牌 |
| tokenType | 固定 Bearer |
| expiresAt | 登录成功时 `Date.now() + expiresIn × 1000` |
| user | 昵称与账号展示所需的 id、account、nickname、role |

密码、密码哈希与登录请求对象不持久化。刷新时先检查存储结构和 expiresAt，合法且尚未过期才恢复展示；无效 JSON、缺失字段或已过期会话会被清理。浏览器禁用存储时允许页面内存登录，但不能保证刷新后恢复。

刷新不重发账号密码，不请求 `/api/auth/login` 或 `/api/auth/me`。后续通过共享 `http` 实例调用相对路径业务接口时自动附加：

```http
Authorization: Bearer <accessToken>
```

不会把 token、密码或整个 user 放入 URL，不把 user 或 expiresIn 附加到业务 body。登录端点和绝对地址请求不自动附加令牌。页面刷新时加载的 HTML 本身不通过该 Axios 拦截器发送 token；真正的身份传递发生在后续 API 请求。

恢复前端登录展示不等于后端已经认可身份；后端按已有规则处理每次携带令牌的请求。当前前端不通过 me 查询最新昵称、禁用状态或角色。后端既有仅解码 JWT 的选择及其边界见最终约定，不因本次前端登录而改变。

## 5. 过期与退出

- 前端根据 expiresAt 安排到期清理，并在发送业务请求前再次检查时间。
- HTTP 401 或业务 `code: 401` 仅在失败请求携带的 Authorization 与当前会话匹配时清理会话；旧请求失败不清理已切换的新 token，会话仍有效时登录请求失败不清理原会话。
- 清理后入口恢复未登录图标，用户点击重新打开登录框；不自动弹出，不自动续期或循环重试。
- 退出登录只清除本地会话和存储，不调用尚未提供的注销接口，不表示服务端撤销 token。
- 会话按标签页保存，刷新仍有效，关闭标签页后结束；不做标签页之间的登录状态同步，后续是否需要跨标签页共享另行决定。
- 403 专用权限页面、服务端刷新/撤销、账户禁用与角色变更后的即时生效策略仍待实现或确认。
