## 1. 新增与修改共用保存 POST

```http
POST /api/merchant/products/save
Authorization: Bearer <当前登录令牌>
Content-Type: application/json
```

新增不提交 id，修改提交字符串 id；后端按有无 id 区分新增和修改。新增默认下架（status=2），修改保留原上下架状态，保存 body 不提交 status。成功沿用 Result，数字 code=200 为成功，允许 data=null；前端不依赖返回完整商品，而是重新查询列表及顶部统计。

修改示例（新增时省略 id）：

```json
{
  "id": "101",
  "name": "工程测量全站仪",
  "model": "TS-02",
  "coverUrl": "https://example.com/product.webp",
  "categoryId": 1,
  "price": 1980000,
  "stock": 12,
  "isSeckill": true,
  "seckillStartTime": "2026-10-23T18:00:00",
  "seckillEndTime": "2026-10-23T20:00:00"
}
```

字段沿用 GET 的驼峰命名。数据库 is_seckill=1/0，对应 JSON isSeckill=true/false；不同时发送两种命名或数字布尔。价格单位为整数分，分类号为数字 0～5，ID 为字符串。头图可输入 HTTP/HTTPS URL，空值提交 null；本轮不新增图片上传服务。

保存仅提交上述可编辑字段；商品归属、销量、详情图、删除标记等未展示字段不提交。后端修改时只更新约定字段，不能把本次未提交字段覆盖为空。现有列表已含本次编辑所需字段，暂不额外请求消费者详情，也不从列表臆造商品说明或详情图片。

## 2. 共用弹窗

- 新增打开空表单，标题“新增商品”；修改回显名称、型号、头图、分类、价格、库存、秒杀标记和起止时间，标题“修改商品”。
- 表单增加“是否为秒杀商品”开关。开启显示并要求开始、结束时间；关闭时无论草稿是否残留时间，都提交两项 null。
- 秒杀起止按北京时间 Asia/Shanghai 输入和回显，提交不带偏移的日期时间；结束必须晚于开始。非法或缺失时间阻止保存。
- 沿用名称 1～80 字、型号最多 80 字、价格大于 0 且最多两位小数、不超过 99,999,999 元、库存 0～999,999 的表单限制；分类必须是 0～5。价格通过字符串和整数分转换，避免浮点乘法误差。
- 保存中禁用重复提交及关闭弹窗；失败保留用户输入并显示错误，不自动重试；成功关闭并刷新列表、统计。修改保存保持当前筛选与页码；新增保存回到全部商品第一页。

## 3. 上下架独立 POST

```http
POST /api/merchant/products/101/status
Authorization: Bearer <当前登录令牌>
Content-Type: application/json
```

```json
{ "status": 2 }
```

status=1 上架、status=2 下架；请求不携带整份商品资料。原始 status=1 显示下架按钮，其余显示上架。上架前前端检查有库存和有效正价格；最终合法性仍由后端校验，状态切换不改变秒杀时间。

成功允许 `{ "code": 200, "message": "OK", "data": null }`，之后刷新列表和统计；失败不本地伪造状态变化。请求中阻止重复操作；本轮使用行按钮直接操作，不额外增加确认弹窗。

## 4. 会话与错误

复用共享 HTTP 客户端及 expectedAuthorization，不能由前端指定 merchantId。后端负责商家角色、商品归属及字段校验。HTTP/业务 401 沿用登录失效处理，403 显示无权限；其他业务消息以纯文本展示，异常或网络失败显示错误。

切换账号、退出、离开页面清空弹窗、结果和等待，取消旧请求等待，旧响应不能关闭新弹窗、刷新新账号数据或显示成功。取消等待不能撤销已经到达后端的写入；失败不自动重试，避免重复新增。
