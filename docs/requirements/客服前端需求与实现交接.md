# 客服前端需求与实现交接

更新时间：2026-10-16\
状态：客服前端已实现并验证；真实客服服务或通信接口尚未接入。

## 1. 已确认的项目范围

用户确认将求职 Demo 收敛为单商家运营，项目名称「经纬智选」及代码仓库、数据库名称不变。展示和运营只使用一个商家，不建设商家入驻、店铺选择、多店客服分配或平台仲裁。现有用户/商家角色、账号注册登录、merchant_id 和商品归属校验保留，不因单商家演示放宽授权或修改数据库。

本轮先更新 Require，再直接实现客服前端。当前没有确认真人/AI接待后端，因此本期做统一商家客服界面与明确标注的本地模拟回复，不调用大模型、不伪装真人在线，不与既有后期 AI 导购混用。

## 2. 界面与入口

- 应用根组件挂载一个全站共享客服组件，首页、商品列表、商品详情、购物车和订单页面右下角均显示「联系客服」。
- 桌面点击打开右侧聊天抽屉，手机展开为全屏；沿用商城颜色、字体和 Element Plus，不改现有页面布局。
- 抽屉标题「经纬智选客服」，持续展示「前端演示」和「模拟回复，消息不会发送给真实客服」提示。
- 顶部可关闭、清空演示会话；正文为消息历史和快捷问题，底部固定输入框与发送按钮。显示模拟回复中的状态及未读提示。
- 使用现有 Dialog/Drawer 的焦点管理，支持 Escape 关闭、键盘访问和可读的按钮名称。聊天滚动仅影响消息区，打开后定位至最新消息。

## 3. 消息与会话

- 游客可以体验前端咨询，不请求登录或创建额外身份。成功登录、退出、到期或切换账户时清空旧会话、草稿、待发送上下文、未读及尚未到达的模拟回复。
- 支持纯文本消息；空白不可发送，输入框最多 500 个 UTF-16 字符，发送时去除首尾空白；状态层同样拒绝去空白后超限的内容。Enter 发送，Shift+Enter 换行，中文输入法组合期间 Enter 不发送。
- 用户发送后显示本地消息，短延迟给出固定演示回复；明确区别本地发送与真实送达，不展示真人已读或在线承诺。
- 快捷问题包含商品咨询、发货时间、物流查询和售后问题，回复只说明如何咨询或在哪里查看信息，不编造发货时效、售后承诺、真实库存或物流状态。
- 关闭抽屉保留本页内存中的会话、草稿及回复，关闭期间到达的回复增加未读数；打开后清除未读。
- 切换前端路由不丢失会话。刷新清空，不持久化到 localStorage/sessionStorage，不跨标签共享客服消息。
- 清空会话重置欢迎语并取消待到达回复；组件或应用释放时清理计时器。文本按普通文本渲染，不使用 v-html。
- 本期不做图片/文件/语音、客服工作台、排队、人工转接、真实消息重试、推送或历史记录后端。

## 4. 商品与订单咨询

- 成功加载的商品详情提供「咨询商品」，打开客服并预览商品卡片；订单详情提供「联系商家客服」，打开并预览订单卡片。
- 上下文先预览，由用户点击「发送商品/订单」才加入会话；可移除预览，不在点击入口时自动发送。
- 商品卡片只含商品 ID、名称、型号和展示价格；订单卡片只含订单 ID、订单号、状态和金额，不携带收货人、电话、地址、token 或密码。
- 订单仅允许从当前会话已加载的详情构建上下文，失败/未登录/不可访问状态不显示关联咨询按钮。显示卡片中的订单信息是本地快照，不作为支付或退款依据。
- 发送后保留可辨识的上下文卡片，再按固定脚本模拟回复；不调用商品、订单或客服写接口。

## 5. 实施结构与边界

- `src/stores/customerService.ts`：全局聊天状态、文本/上下文消息、模拟计时器、未读、身份变化隔离。
- `src/types/customerService.ts`：上下文和消息类型。
- `src/constants/customerService.ts`：欢迎语、快捷问题和固定演示答复。
- `src/components/storefront/CustomerServiceWidget.vue`：浮动按钮、抽屉、消息、快捷问题及输入。
- `src/components/storefront/CustomerServiceContext.vue`：最小化商品/订单卡片展示。
- `src/composables/useCustomerServiceContext.ts`：将已加载的商品/订单转换为最小咨询上下文，供详情入口使用。
- `src/App.vue`：只挂载一次，保证路由切换后会话继续。
- 不新增客服网络接口、SSE/WebSocket、Java/Python服务或数据库表；未来真实接入另行确认协议与消息归属。

## 6. 验收

1. 全站入口、桌面抽屉、手机全屏、关闭/重开和未读提示正常；手机无横向溢出。
2. 文本、快捷问题、组合输入保护、长度限制、明确模拟标记可用。
3. 商品/订单卡片先预览后发送，金额 0 与未知分开，不包含收货信息。
4. 路由切换保留会话；身份变化及清空后迟到回复不再出现。
5. 全量自动测试、类型检查、构建与代码检查通过，浏览器验证交互。
