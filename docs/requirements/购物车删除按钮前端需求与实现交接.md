## DELETE 接口约定

```http
DELETE /api/cart/123
Authorization: Bearer <token>
```

- 路径为 /api/cart/{productId}，使用商品 ID 的正整数字符串，保留大整数精度；不是 cartItemId。
- 不发送请求体，不传 quantity、userId、价格、库存或内部身份头，认证由统一 HTTP 客户端处理。
- 成功要求 HTTP 成功且响应业务 code 为数字 200，前端不依赖成功 data，约定示例：

```json
{"code":200,"message":"购物车商品删除成功","data":null}
```

- 后端需按可信当前 user_id 与 product_id 限定删除自己的购物车记录，不接受客户端自报当前用户，不得按商品 ID 删除其他用户购物车。
- 删除只作用于 cart_item，不删除商品本身，不扣减/回补库存，不要求商品仍有货或在售；缺货、下架、失效商品也应可删除。
- 建议目标记录已不存在时仍返回成功，保持重复 DELETE 的幂等效果。前端不自动重试，也不把普通 404/5xx 或畸形响应当作成功。
- 401 沿用网关登录处理；403、非法参数和服务异常沿用 code/message/data。网络中断或超时可能已经落库，前端提示刷新确认结果。

## 页面行为

- 每个商品行末尾都有独立“删除”按钮，包括缺货、下架、失效及库存/价格待确认商品。桌面保留操作列，手机按钮位于对应卡片末尾。
- 点行内按钮先弹出 ElPopconfirm 气泡，标题包含对应商品名称，按钮为“取消”和“删除”，确认按钮为 danger 样式；不采用示例中必须先取消才可确认的额外限制。
- 仅气泡 confirm 事件触发 DELETE。取消、关闭或点击外部不发删除请求、不移除商品。取消确认不影响原本正在进行的数量编辑。
- 确认后按该行 productId 立即发送 DELETE，不对删除请求做数量防抖。请求期间禁用该行删除按钮与数量输入，防止重复提交；其他商品可以独立操作，刷新购物车在有在途删除时禁用。
- 等待响应期间保留该行及已确认数量、勾选和金额。仅成功后移除该行、清除勾选/错误并重算款数、件数、参考合计，其他行及勾选保留。最后一行成功删除后进入既有空态。
- 业务失败、HTTP 错误、超时/断网或畸形响应均保留该行与合计，在行下显示错误并允许再次确认重试，不伪装删除成功，不自动回退模拟数据。
- 进入实际删除时取消该行尚未发送的数量防抖，并取消前端等待中的数量 PUT、忽略其迟到反馈，其他行数量计时不受影响。取消前端请求不代表撤销服务端可能已执行的数量更新。
- 退出、过期、切账号或离开页面时取消删除等待，清空旧状态；迟到响应不删除新账号的商品或覆盖新错误，旧 401 不清除新会话。
- 匹配当前令牌的 401 显示既有登录引导；403、普通错误不清除有效登录。数量控制与状态仍按 cartItemId 管理，网络删除按 productId 发出。
