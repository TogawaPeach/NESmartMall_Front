# 购物车纸质小票结算前端需求与实现交接
> 2026-10-19 更新：本文的本地直接成功、查价及“不生成订单”行为已被[订单创建与模拟支付交接](./订单创建与模拟支付前端开发交接.md)取代。保留本文作为纸质样式与历史验收记录。


更新时间：2026-10-18

## 当前范围与状态

用户确认：购物车点击结算后，在当前页面缓慢从下向上弹出居中的小型纸质支付小票；纸张使用暖米白色。本轮只做前端，含模拟支付与成功状态，不接结算或支付后端。

本轮已实现，替代此前购物车文档中“购买按钮暂未开放、不做购买弹窗”的阶段性描述。已有购物车查询、数量修改和删除继续使用原接口；本次不增加交易写请求，不创建订单、不扣减库存、不实际扣款。

## 入口与数据

- `/cart` 底部原禁用购买按钮改为“结算（已选款数）”。
- 购物车加载成功、有可结算的勾选商品、合计可安全计算，且没有等待防抖的数量编辑、在途数量更新或删除时，按钮可用；未勾选时禁用。
- 复用 `useCart` 的 `selectedItems`、`totalFen`、`selectedQuantity`，只展示已选且可购买的条目。缺货、下架、失效、库存或价格待确认的条目沿用原有不可选规则。
- 小票包含商品名称、可选型号、单价、数量、每行小计、款数、总件数和合计。金额继续按整数分计算，通过既有格式函数转换为人民币元；0 元商品可展示和演示支付。
- 数量修改完成前不开放结算，避免输入中数量与已确认金额不一致；账号、购物车状态、所选商品或金额变化时关闭原小票。

## 视觉与动效

- 使用当前页面的模态弹层，不打开新页面、不修改 URL。背景轻微变暗并模糊，小票居中。
- 小票宽度上限 380px，窄屏限制在视口宽度减 40px；暖米白纸色、轻纸纹、虚线分隔、底部锯齿纸边和柔和阴影。
- 保留“经纬智选”品牌；次要文字使用暖灰褐色，在深色商城主题中小票仍为浅纸色。
- 从视口下方上浮到中央，位移动画约 800ms，背景及透明度渐变约 650ms；关闭约 280ms。遵循系统减少动态效果设置。
- 小票高度不超过视口减 64px，标题区保留，内容区超高可滚动；商品明细另设最大高度，长名称换行。

## 模拟支付与关闭

- 初次打开为待支付状态，提供明确标注的“模拟支付”与本次合计金额；按钮下说明不会生成订单或实际扣款。
- 点击后只在组件内切换为“模拟支付成功”，显示成功标记、演示金额和“完成，继续逛逛”。不发支付请求，不持久化成功状态。
- 当前模拟支付成功不删除购物车商品、不取消勾选，也不向订单页面插入演示订单；后续真实结算清理按下文 RabbitMQ 约定实施。
- 完成按钮、右上角关闭、Esc 或点击遮罩均可关闭；再次结算重新进入待支付状态。
- 使用 Element Plus `ElDialog` 提供模态焦点约束、滚动锁定与关闭支持。标题关联对话框，关闭按钮有中文无障碍名称，成功状态使用礼貌播报区域；支付按钮保持同一个 DOM 元素以保留键盘焦点。

## 2026-10-19 模拟支付前查询价格与二次确认

本节替代上文“点击模拟支付直接切换成功、不发查询请求”的阶段性约定。项目继续用于求职 Demo，确认支付为本地演示成功。

- 保留购物车纸质小票；点击“模拟支付”后打开“确认模拟支付”弹窗，先展示查询中状态。
- 复用统一 HTTP 客户端发送 `GET /api/cart`，沿用 Bearer 认证与网关身份；后端返回当前购物车商品价格，前端按本次勾选条目筛选，以最新单价乘已确认数量，按整数分汇总。不新增后端接口，不上传前端价格或用户 ID。
- 查询成功展示“这些商品总价为 ¥___，是否支付？”，同步更新小票商品单价、行小计及合计。零元允许确认；未选商品不参与合计。
- 选择“是，确认支付”直接显示“支付成功”，不发送支付写请求、不创建订单、不扣款、不删除购物车商品或发送 RabbitMQ 消息。选择“否，暂不支付”、关闭或 Esc 返回待支付小票，再次点击会重新查询价格。
- 查询失败不回退旧金额，提供“重新查询”。条目消失、商品标识/数量变化、不可购买、价格为空或金额溢出时阻止确认，提示刷新购物车。
- 查询中阻止重复点击和提前确认；关闭小票、选择变化、退出/切换账号或组件卸载均清空状态并取消查询，忽略迟到响应。再次打开小票重新进入待支付。
- `useCheckoutPayment.ts` 管理查询与演示状态，`CheckoutReceipt.vue` 展示弹窗。确认成功后的弹窗关闭通知不清除成功状态。
