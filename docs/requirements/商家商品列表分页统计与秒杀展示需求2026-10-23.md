## 1. 范围与现状

商家登录后进入 `/merchant/products`。前端已接入独立统计、分页、状态筛选及秒杀阶段展示，新增、编辑及上下架暂禁用；后端统计和分页查询代码已写入，尚未完成真实联调。此前五件内存演示商品是历史实现，不作为当前查询结果。

沿用单商家自营定位、现有 Bearer 登录与统一 Result。商家列表覆盖普通商品和秒杀商品、上架和下架商品，不能直接复用消费者仅查询在售商品的 SQL 条件。

本次实现商品列表与统计查询，不实现新增、编辑、上下架、图片上传或秒杀交易，不修改数据库。

## 2. 首次加载与刷新

首次打开页面，并行发送两个 GET，无请求体，均携带现有 `Authorization: Bearer <登录令牌>`：

```http
GET /api/merchant/products/page?pageNum=1&pageSize=8
GET /api/merchant/products/stats
```

- 列表接口返回当前页及当前筛选条件下的总数；统计接口返回整个店铺的全部、在售、下架数量，不受列表页码或状态影响。
- 沿用现有商家页每页 8 件；只有 5 件就返回实际 5 件，不补齐演示商品，不把总数固定为 5。
- 翻页、切换状态只重新请求列表；状态变化时回到第 1 页，翻页保留状态条件。不提供商家搜索，也不发送 keyword。
- 后续新增、编辑或上下架成功后刷新列表和统计，失败不伪造结果。筛选后的末页变空时，按最新 total 纠正页码并重新查询。
- 列表和统计分别处理加载、失败和重试。失败不能显示为 0 件，也不能回退演示数据。
- 取消旧请求等待并阻止旧响应覆盖新条件或新身份的数据。

## 3. 分页接口

路径：`GET /api/merchant/products/page`。此路径取代旧商家接口草案中未定稿的 `GET /api/merchant/products` 列表路径，不影响消费者商品接口。

| 参数 | 约定 |
| --- | --- |
| pageNum | 从 1 开始的正整数，首次为 1 |
| pageSize | 默认 8，沿用前端请求值；按用户要求不新增页大小及上限校验 |
| status | 可选；全部不传，`on-sale` 在售，`off-shelf` 下架；后端映射数据库状态 |

```http
GET /api/merchant/products/page?pageNum=1&pageSize=8
GET /api/merchant/products/page?status=on-sale&pageNum=1&pageSize=8
GET /api/merchant/products/page?status=off-shelf&pageNum=1&pageSize=8
GET /api/merchant/products/page?status=off-shelf&pageNum=2&pageSize=8
```

当前后端先排除逻辑删除，再按状态筛选，最后按商品 ID 降序分页；当前未按 merchant_id 限定归属。`total` 是所有符合当前条件的商品总数，不是当前页条数。后端沿用 MyBatis/XML 与 PageHelper，前端使用 Element Plus 分页组件，直接使用响应 total；不能只过滤本页或再次切片冒充服务端分页。

已写入商品 ID 降序及 PageHelper `setReasonable(false)`；当前页面请求每页 8 件。正常正整数页码超过末页时保留请求页码，返回当前筛选 total 与空 list，由前端纠正页码后重查。Service 不新增 pageNum、pageSize 或 status 的参数校验，Controller 仍以 Integer 接收分页参数；非法类型的绑定行为由 Spring 处理。XML 仅识别 on-sale、off-shelf；不传或其他值均不附加状态条件。

## 4. 单个商品对象

| 字段 | 类型及展示用途 |
| --- | --- |
| id | 字符串商品 ID，供编号展示和后续编辑、上下架定位；BIGINT 不以不安全的 JS number 传输 |
| coverUrl | 头图 URL；缺失可 null，前端缺图或加载失败使用图片占位 |
| name | 商品名称字符串 |
| model | 型号字符串；为空显示“未填写型号” |
| categoryId | 数字分类号；用户说明数据库为 0～5，前端按映射转为中文字符串，不要求后端返回中文分类名 |
| price | 售价，非负整数分；前端展示两位小数元，缺失不能按 0 元处理 |
| stock | 非负整数库存，0 为真实库存值 |
| status | 原始商品状态，沿用现有表设计：0 草稿、1 上架、2 下架；不写入秒杀阶段 |
| isSeckill | 布尔秒杀标记，沿用既有秒杀契约，区分普通商品与起止时间异常的秒杀商品 |
| seckillStartTime | 秒杀开始日期时间；普通商品为空，秒杀商品正常情况下有值 |
| seckillEndTime | 秒杀结束日期时间；普通商品为空，秒杀商品正常情况下有值 |

用户允许普通商品时间为 null 或空值。接口建议统一输出两个字段且值为 null；前端兼容 null、空字符串或字段缺失，归一为空。秒杀商品两项时间应有效且结束晚于开始；不能仅凭时间为空就将 `isSeckill: true` 的异常数据视为普通商品。

分类沿用现有 1～5 映射，用户已确认 0 显示“未分类”；后端将数据库空分类映射为 0：

| categoryId | 前端文案 |
| --- | --- |
| 0 | 未分类 |
| 1 | 全站仪 |
| 2 | GNSS / RTK |
| 3 | 水准仪 |
| 4 | 测距仪 |
| 5 | 配件 |

“全部”属于查询范围，不是一件商品的分类；未知编号也不能映射成“全部”。现有商家类型只有五个分类字符串 key，接入时需要补齐数字映射及 0 的处理。

## 5. 秒杀状态展示

用户确认：普通商品继续显示原上下架状态；秒杀商品在前端状态栏替换为活动阶段文案。

| 时间条件 | 文案 |
| --- | --- |
| 当前时间 < seckillStartTime | 未开始 |
| seckillStartTime <= 当前时间 < seckillEndTime | 正在秒杀 |

时间沿用既有格式 `yyyy-MM-dd'T'HH:mm:ss`（可含毫秒），无偏移的时间按北京时间 `Asia/Shanghai` 解释；前端显式按此时区解析，避免设备默认时区改变边界。计时只更新本地显示，不每秒请求列表。

原始 `status` 与活动阶段分开保存；状态栏文案替换不改变上下架状态、筛选、操作按钮或统计。库存 0 也不能自行改写上下架状态。展示不代表可购买，交易资格仍由后端校验。

以下为补充建议，未由用户确认，接入前应落定：

- 当前时间达到或超过结束时间：建议显示“已结束”。
- 已下架秒杀商品：建议优先显示“已下架”，可额外展示秒杀阶段；用户目前只确认替换文案，尚未确定此优先级。
- 秒杀时间缺失、非法或起止颠倒：建议显示“秒杀时间异常”，不能显示“正在秒杀”。
- 浏览器时间偏移：如需精确计时，后续约定服务端时间校准；本轮未新增 serverTime 字段。

## 6. 全店统计接口

路径：`GET /api/merchant/products/stats`，Controller 不声明列表 status 或页码参数。

```json
{
  "code": 200,
  "message": "OK",
  "data": {
    "allCount": 100,
    "onSaleCount": 80,
    "offShelfCount": 20
  }
}
```

- 当前统计范围为 product 表全部未逻辑删除商品，同时包含普通和秒杀商品；未增加 merchant_id 归属过滤。`allCount` 表示该范围全部数量。
- `onSaleCount` 按原始上架状态统计，`offShelfCount` 按原始下架状态统计，不受秒杀阶段或库存是否为零影响。
- 不用当前页 list.length 算总数，不用本页在售数算全店在售数，也不用 `allCount - onSaleCount` 代替真实下架数。
- 已按 review 确定：全部包含 0 草稿，在售只统计 1，下架只统计 2；存在草稿时全部大于另外两项之和。上面示例假设无草稿，不将 0 当 2。
- 后端可一次条件聚合取得三项，不将所有商品传前端计数。两个独立 GET 不承诺并发写入下读取同一快照。

## 7. 权限、错误与验收

目标为两接口必须登录且为商家，前端携带既有 Bearer，不发送 merchantId。当前两接口经过网关 JWT 校验；只有 stats 额外要求 MERCHANT，page 尚未补角色限制；当前 SQL 均未按可信身份过滤商品归属，product 也未新增接口级角色校验。剩余权限要求待后续实现验收，不只依赖前端路由守卫。

成功沿用 `{ code, message, data }`，仅 `code: 200` 为业务成功。401 进入既有登录流程，403 提示无权限；网络、业务和响应结构错误显示失败并允许重试。空列表为 `list: []`、`total: 0`，空店铺三项统计为 0。

后续实施验收：

1. 首次两个 GET、第一页最多 8 件、不足时显示实际数量，刷新不恢复演示商品。
2. 多页 total、状态筛选、换状态回第一页、翻页保留条件、末页和越界纠正；不发送搜索词，顶部统计保持独立口径。
3. 单个对象包含头图、名称、型号、数字分类、分单位售价、库存、原始状态及秒杀标记和时间；字符串 ID、图片失败、0 库存正确处理。
4. 普通商品时间为空仍正常展示；秒杀开始前显示“未开始”，开始时显示“正在秒杀”，结束边界按最终确认规则；北京时间解析一致。
5. 分类 0 为未分类，全部统计包含草稿；已结束、已下架秒杀和异常时间展示规则按最终前端约定核验。
6. 后续写操作成功刷新列表和统计，失败不伪造结果；旧请求不覆盖新状态。
7. 未登录、普通用户、商家范围隔离、空结果及列表/统计独立失败重试。
