# 商品详情页需求

更新时间：2026-10-15\
需求编号：005\
文档状态：前端已按最新单次请求约定完成适配并通过自动化测试与构建，验证见第 12 节；真实 gateway 和后端数据联调待验收。本次只修改前端项目代码、测试及文档，未修改后端或数据库。

最新决定取代此前“先查入口、再查内容”及“新增表保存详情路径”的要求。点击商品后在新标签页打开 /products/{id}，页面直接请求 GET /api/products/{id} 获取商品内容。

## 1. 当前状态与范围

前端保留现有商品详情布局和新标签页导航，已移除入口读取及入口未配置状态，加载、刷新、直接访问、重试和登录恢复均直接调用 GET /api/products/{id}。旧版验证仅作历史记录，见第 10 节；本次实际验证见第 12 节。

商品介绍图片保存在 product.detail_image_urls，统一库存保存在 product.stock。每个商品只有一个型号，model 为普通展示字段，不建设 SKU 选择器。平台保存外部图片链接，不下载图片。本阶段不包含订单、购物车写入、库存扣减或回补。

## 2. 服务与页面职责

- 前端根据商品 ID 生成站内页面路径 /products/{id}，保留原生新标签链接。
- gateway 负责受保护 API 的登录和令牌校验；商品服务不重复解析 JWT，不新增详情公开白名单。
- mall-product-service 按 ID 读取 product，仅返回已上架且未删除商品（status = 1、is_deleted = 0）；查不到统一返回“商品不存在”。
- 取消 GET /api/products/{id}/detail-entry、productId/detailPath 入口响应及 product_detail_page 路径关联表的建设与读取要求。若数据库已有相关表，本次不操作它，详情读取不依赖它。
- 商户商品维护与归属检查属于后续写入功能，不因简化详情读取而取消。

## 3. 点击导航与单次请求约定

1. 首页、分类列表、搜索结果均通过原生链接在新标签页打开 /products/{id}，原页面保留，支持键盘和右键操作。
2. 新页加载、刷新或直接输入 URL 时，直接请求 GET /api/products/{id}，不先查询入口、不请求页面路径。
3. 请求复用现有 HTTP 客户端和 Bearer token；开发环境的 5173/api 请求由 Vite 代理到 8080 gateway，再转发商品服务。
4. 内容响应沿用第 8 节字段；保留响应商品 ID 一致性、字段类型、价格单位和图片数组适配，去掉 productId/detailPath 入口专用校验。
5. 401 走现有登录提示，登录后重新请求详情；403 显示无权限；404 显示商品不可访问，服务故障允许重试。
6. detailImages 为 [] 时仍正常展示商品名称、价格、库存等信息，仅图片区域显示“暂无详情图片”。
7. 部署支持 SPA 历史路由回退；/products/{id} 刷新可加载页面。不将 token 或用户身份拼接进页面或图片 URL。

仅保留 GET /api/products/{id} 作为详情读取接口。现有首页 GET /api/products、分页 GET /api/products/page 及其响应格式保持原约定，/page 不得被当作商品 ID。

## 4. 事务与缓存

详情为商品服务内的单次只读查询，不引入分布式事务、额外微服务或本期缓存。后期 Redis 缓存商品详情时按商品 ID、商品状态与数据版本设计，商品上下架、删除及内容变化后处理缓存失效；详见 [微服务基础设施与通信需求.md](./微服务基础设施与通信需求.md)。

## 7. 商品介绍图片与库存（2026-10-15 最终确认）

- 用户自行收集图片链接，平台只保存完整外部图片链接，不下载到本地，不建设图片上传或对象存储。
- 商品介绍图片直接保存于 product.detail_image_urls，不另建 product_detail 或 product_detail_image 内容表。一个商品仍然对应 product 的一行，沿用原有自增主键 id。
- detail_image_urls 为 JSON 数组，保存该商品全部介绍图链接；长图拆成多段时，多个链接仍存于同一行。数组顺序就是展示顺序，非空且默认 []。
- 新增、删除和排序图片时整组更新数组。后端校验数组元素为非空的完整 HTTP/HTTPS 图片链接，返回真正的 JSON 数组，前端依次展示；无图片时使用空数组 []。
- 封面仍存于 product.cover_image_url；首页与列表不返回详情图片数组，进入详情页后再按 id 获取。页面路径由前端按 /products/{id} 生成，不再依赖 product_detail_page 路径关联表。
- 统一库存保存在 product.stock，类型 INT UNSIGNED NOT NULL DEFAULT 0，单位件；未来如需分规格库存，再另行设计 SKU。本次未实现扣减、回补或订单联动。
- 用户说明 product 已有 25 条数据，并授权生成 20～200 件的随机测试库存。按全部现有行更新，不依赖自增 id 连续；这不是已核验的真实库存，本助手未连接数据库执行或确认结果。
- 详情与库存字段约定见本节和第 8 节；[商品表设计.md](./商品表设计.md) 保留历史主表设计。本轮不新增或执行 SQL，不重复加列、不覆盖测试库存，实际列由后端另行核对。前端已改为单次请求，后端真实联调尚待完成。

## 8. 商品详情内容接口与单型号（2026-10-15 确认）

GET /api/products/{id} 经过 gateway 转发到 mall-product-service；只读取当前可展示商品。API 使用现有 HTTP 客户端与登录令牌；不新增公开白名单，访问策略由网关决定，前端处理 401/403。路径参数 id 使用十进制正整数，BIGINT 以字符串传递，避免 JavaScript 精度丢失。

成功响应：

```json
{
  "code": 200,
  "message": "OK",
  "data": {
    "id": "123",
    "name": "全站仪",
    "model": "NTS-332R",
    "coverUrl": "https://example.com/product-cover.jpg",
    "price": 990000,
    "sales": 36,
    "stock": 20,
    "detailImages": [
      "https://example.com/detail-1.jpg",
      "https://example.com/detail-2.jpg"
    ]
  }
}
```

| 字段 | 类型与规则 | 数据来源/展示 |
| --- | --- | --- |
| id | string，和请求商品一致 | product.id；兼容安全正整数 number，超出安全范围必须 string |
| name | 非空 string | product.name；右侧商品标题 |
| model | string 或 null，可省略 | product.model；名称下方展示，有且仅有一个型号，不做选择器；缺失时隐藏 |
| coverUrl | 完整 HTTP/HTTPS 图片地址或 null | product.cover_image_url；左侧方形头图，失败或缺失显示占位 |
| price | 非负安全整数分或 null | product.price；除以 100 显示人民币，0 正常展示，null 显示“价格待确认” |
| sales | 非负安全整数 | product.sales_count；显示“已售 N 件”，统计口径以后端确认为准 |
| stock | 非负安全整数 | product.stock；显示“库存 N 件”，0 显示缺货并禁用两个购买按钮 |
| detailImages | string[]，无图为 [] | product.detail_image_urls；返回真实 JSON 数组，不能是 JSON 字符串；保持顺序，完整 HTTP/HTTPS 地址 |

详情响应沿用 Result，仅 code: 200 视为业务成功。401 需登录，403 无访问权限，404 表示商品不存在、删除或下架，后端统一提示“商品不存在”。其他业务失败显示查询失败并允许重试，不依赖 message 文本判断状态。无详情图片是成功结果，返回 detailImages: [] 并显示“暂无详情图片”；不再返回或依赖 DETAIL_NOT_CONFIGURED，也不保留入口未配置的页面状态。

首页/分页接口仍不返回详情图片数组。库存、价格和销量从详情接口重新读取，不直接把列表卡片上的值当作最新详情。

## 9. 页面布局与本期前端范围

- 延续现有商城页头、配色和宽度。桌面端顶部为左右两列：左侧方形商品头图，右侧从上至下为名称、单个型号、价格与销售库存、购买按钮。
- 价格位于左侧，右侧两行分别为“已售 N 件”和“库存 N 件”。按钮并排：左侧“立即购买”为实心，右侧“加入购物车”为空心描边。
- 下方独立“商品详情”区域横跨两列，按 detailImages 顺序自上而下展示，保持图片原始比例，宽度不超过容器，不下载或上传图片。空数组显示“暂无详情图片”，单张加载失败显示对应占位并保留其余图片。
- 窄屏上下排列，先头图、后商品信息，再展示详情图片；按钮仍按购买在左、购物车在右。
- 覆盖加载占位、成功、缺货、暂无详情图片、商品不可访问、登录提示、错误与重试。切换商品、登录状态变化或离开页面时取消旧请求，旧响应不能覆盖当前状态。
- 本期实现页面、只读接口对接与按钮外观。订单、购物车 API 尚未约定；有库存且价格明确时按钮可点击并提示“购买功能暂未开放”或“购物车功能暂未开放”，不发出写请求，不伪装为购买或加入成功。价格待确认时禁用两个按钮。
- 后端接口和数据库由后端任务实现；此轮不修改后端代码、不执行 SQL，不将前端测试数据作为真实商品展示。
