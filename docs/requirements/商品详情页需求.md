# 商品详情页需求

更新时间：2026-10-14\
需求编号：005\
文档状态：站内链接需求已确认，接口与数据字段为草案；本次只写文档，不修改应用代码或执行建表。

本文承接 [需求.md](./需求.md) 的首页与商品列表。用户已确认：新增表保存商品详情页的商城站内路径，例如 /products/123；点击对应商品后进入其详情页。链接由商户提前维护、点击时读取的流程按本次讨论整理，自动生成路径等细节在实施时确定。

## 1. 当前状态与范围

当前商品主表只保存封面地址 cover_image_url，未包含详情页路径。前端商品卡片仅展示商品，没有点击跳转；路由中已有 /products 列表页，尚无 /products/:id 详情页。后端目前只有首页与分页查询，详情入口、详情内容接口和对应表均尚未实现。

本需求先明确商品与站内详情页的关联、点击导航及访问校验。商品详情页需要展示的图片、描述、参数、SKU、库存或购买功能尚未明确，另行补充内容模型；保存一个路径不等于详情页内容已经存在。

## 2. 服务归属与关联表草案

新增表建议名为 product_detail_page，与 product 主表同属 mall-product-service，存放于商品数据库 nesmartmall_product。新增表不单独拆出详情服务。

| 字段或约束 | 建议设计 |
| --- | --- |
| product_id | BIGINT，关联商品 ID；作为主键或唯一键，初期每个商品对应一个有效详情路径 |
| detail_path | 非空字符串，保存规范化站内相对路径，例如 /products/123；长度与唯一索引在表设计阶段确定 |
| created_at、updated_at | 维护时间，精度与现有商品表统一 |

详情路径使用站内相对路径，部署时不保存 localhost、环境域名、JWT 或用户身份。当前建议统一为 /products/{商品ID}，与已有 /products 列表路由并列。路径必须符合约定格式并对应同一个 product_id，不能指向另一商品、商户后台或外部网站；是否支持自定义 slug 后续另定。

详情关联维护按 product.merchant_id 与解码账户 sub 限定范围，不采用客户端额外提交的所有者参数。商家 ID 复用商家账户 ID，不另依赖商家表。当前选择 JWT 仅解码、不验签，sub 可伪造，不能保证防止冒充其他商家；最新边界见 [账户与登录最终约定.md](./账户与登录最终约定.md)。

历史商品需要按实际页面情况补充关联记录，不能填入不可用占位链接并宣称详情可访问。详情路径的创建、修改、缺失与商品下架或删除的处理需要保持一致；商户后台维护入口尚待开发。

## 3. 点击导航与接口草案

1. 首页与分页列表中的商品卡片提供明确可操作的详情入口，支持鼠标与键盘；两处入口行为一致。
2. 点击时根据商品 ID 取得详情入口信息。建议新增 GET /api/products/{id}/detail-entry，经过网关到商品服务查询关联表。
3. 商品服务检查商品是否可展示、是否存在有效详情关联，返回 Result；成功 data 草案包含 productId（建议 string）和 detailPath（string）。
4. 前端校验返回路径对应当前商品，再导航到站内详情路由。详情页依据商品 ID 获取该商品内容，展示内容接口和字段另行确定，不将 API 地址当成页面路径。
5. 详情页刷新或直接输入 URL 时能匹配详情路由，并重新校验商品可访问状态。部署需支持 SPA 历史路由回退，不能刷新后只得到服务器 404。
6. 商品不存在、已删除或对当前用户不可见时拒绝公开访问；详情关联未配置时显示明确的暂无详情提示，不跳到不存在的页面。业务码及页面提示在联调前统一。

读取入口时继续沿用现有商品接口的 JWT 要求，不因为站内路径公开可见就省略 API 鉴权。首页首次无令牌策略仍按 [登录服务与网关需求.md](./登录服务与网关需求.md) 待确认；不得将 Bearer 令牌拼入页面 URL。

GET /api/products/{id}/detail-entry 为本次新增接口草案；首页成功 data 仍为数组，分页 data 仍为含 list、total、pageNum、pageSize 的对象，现有商品卡片字段与数量规则保持原约定。若后续决定在列表响应附加 detailPath 以减少点击查询，再同步前后端契约。

新详情入口与 /api/products/page 等现有路径不得发生路由歧义。详情内容未开发时，只能验收路径查询及相应阶段入口，不能宣称完整详情体验已经可用。

## 4. 事务与缓存

商品主表与详情关联表在同一商品服务和同一数据源管理，同时维护时使用本地事务。点击读取路径和浏览器页面导航不启动 Seata 全局事务。

Seata 已选为项目后续跨服务写入事务工具；本需求不因新增表而要求分布式事务。调用与事务的整体约定见 [微服务基础设施与通信需求.md](./微服务基础设施与通信需求.md)。

后期可用 Redis 缓存详情入口与内容。路径修改、商品上下架或删除后需失效相关缓存，并继续检查访问状态；缓存范围、TTL、失效时效与并发旧值修复另行细化。

## 5. 待执行验收

| 场景 | 预期结果 |
| --- | --- |
| 首页和商品列表点击同一商品 | 根据同一关联记录进入对应站内详情页，不改变首页销量和分页规则 |
| 路径关联 | 商品 123 对应 /products/123，不能指向其他商品或任意地址 |
| 同一商品重复维护 | 保持唯一有效关联，不生成重复详情记录 |
| 鼠标、键盘与页面刷新 | 详情入口可操作；刷新或直接访问详情 URL 能加载对应页面并重新查询 |
| 无有效 JWT | 受保护入口 API 返回 401 和 Result，前端按登录约定处理 |
| 商品不可展示或不存在 | 不返回可用公开详情；直接输入 URL 或旧缓存不能绕过访问规则 |
| 详情关联缺失 | 显示暂无详情，不跳转到空链接或不存在的页面 |
| 商户使用原始令牌更换商品 ID | 按 merchant_id 拒绝操作他人商品；伪造 sub 的请求无防护保证，不能宣称完成抗越权安全验收 |
| 商品与详情关联共同写入失败 | 本地事务回滚，不留下与此次操作不一致的商品或关联记录 |
| Redis 后期接入 | 路径或商品状态变化后按约定失效并可恢复，不使用长期旧路径绕过状态检查 |

详情页面、内容接口和商户维护入口开发后再执行对应端到端验收；本文未提供 SQL、迁移或应用实现。

## 6. 待细化

- 详情路径由后端按商品 ID 自动生成，还是商户提交并由后端校验；当前按关联表持久保存路径。
- 新表最终字段、长度、唯一约束、关联约束和历史数据回填方案。
- 详情页内容、图片、商品参数、SKU、库存和后续下单入口。
- 同标签页或新标签页导航、路由命名、暂无详情与不可访问页面的提示。
- 详情内容接口、业务错误码、站内路径校验、缓存及商品状态变更的可见时效。
