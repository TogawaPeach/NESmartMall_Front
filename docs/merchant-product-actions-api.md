# 商家商品保存与上下架（前端接入）

2026-10-23：前端已接入共用新增/修改弹窗，以及保存、上下架两个 POST；同时交付此前统计和分页两个 GET。只修改前端及文档，后端和数据库未修改，真实后端尚未联调。商家搜索保持移除。

## 保存商品

`POST /api/merchant/products/save`，复用 Bearer。新增省略 id；修改提交字符串 id。以下是未上架商品修改示例（已上架商品省略 detailImages）：

```json
{
  "id": "101",
  "name": "工程测量全站仪",
  "model": "TS-02",
  "coverUrl": "https://example.com/product.jpg",
  "detailImages": ["https://example.com/detail-1.jpg", "https://example.com/detail-2.jpg"],
  "categoryId": 1,
  "price": 1980000,
  "stock": 12,
  "isSeckill": true,
  "seckillStartTime": "2026-10-23T18:00:00",
  "seckillEndTime": "2026-10-23T20:00:00"
}
```

JSON 使用 boolean isSeckill，后端对应数据库 is_seckill=1/0；普通商品 false 且两个时间都传 null。日期输入、回显和提交均按北京时间解释，保留已有秒和毫秒精度，结束必须晚于开始。价格输入元、请求整数分，使用 BigInt 转换避免分位丢失；0.29 元发送 29。分类数字 0～5、库存整数 0～999999、名称 1～80 字、型号最多 80 字，价格大于 0 且不超过 99,999,999 元。头图 URL 可选，限 HTTP/HTTPS，空值传 null；本轮无上传接口。

新增默认下架由后端设置 status=2，修改保留现有状态，save body 不含 status。商品说明、销量、归属、删除标记等未展示字段不提交；后端只更新约定字段，不能把省略字段清空。弹窗不额外调用消费者详情接口。

详情图片链接为选填动态表单：新建或无图时默认一行，点击“添加图片链接”增加一行，可逐行移除，最后一行移除时清空保留一个空框。新建、草稿和下架商品保存时，去除空白行并按顺序提交 detailImages 数组，全部留空提交 []；非空链接仅允许 HTTP/HTTPS。

用户最新明确上架后不提供详情图查看：status=1 的修改弹窗不显示详情图输入，也不请求详情图；保存其他资料时完全省略 detailImages，后端应保持原图。需先确认下架，才可查看和修改详情图。

未上架商品优先回显分页对象的 detailImages；[] 表示确实无图，字段缺失表示未知，不能直接当作 []。未知时编辑前调用商家 `GET /api/merchant/products/{id}`（Bearer、无请求体），成功 Result.data 至少返回 `{"detailImages":["https://example.com/detail.jpg"]}`，无图须为 []；读取失败不打开空表单覆盖旧图。此新增读取契约仅前端接入，后端需接齐，不能用下架商品不可访问的消费者详情代替。

## 上下架

`POST /api/merchant/products/{id}/status`，请求体仅 `{"status":1}` 上架或 `{"status":2}` 下架，不提交整份商品。当前原始状态为 1 时按钮为下架，其余为上架；前端上架前检查库存与正价格，最终业务合法性仍由后端校验。

下架先打开“确认下架”弹窗，显示商品名。取消/关闭不发 POST；点击确认才发 status=2。提交中禁用重复确认和关闭，失败保留确认框并显示错误，成功关闭、刷新列表和统计。账号变化或离页关闭确认并取消旧等待。上架保持原有直接请求。

两个写接口成功均接受：

```json
{
  "code": 200,
  "message": "OK",
  "data": null
}
```

不依赖 mutation 响应填充列表，成功才重新 GET 列表和统计；新增回全部第 1 页，修改和上下架保留筛选与页码。没有模拟写入，也不把本地状态改动冒充后端成功。

## 交互与会话

新增和修改共用一个弹窗，修改回显列表已有的全部可编辑字段。秒杀开启时展示两个必填日期控件，关闭时隐藏并提交 null；名称等内容保留。保存中禁用字段、提交、取消、Escape 和关闭按钮；操作等待期间阻止其他写操作和替换编辑对象。

失败保留弹窗输入，业务消息按文本展示，HTTP 错误优先处理；不自动重试写入。成功与后续刷新分开处理，即使刷新失败也不再次新增。账号改变、退出或离页立即清理编辑状态与反馈、取消旧等待；请求发送前先同步共享会话并核对 sequence，防止把旧表单提交到新账号；同时复用 expectedAuthorization 保护 dispatch 前的令牌变化。
