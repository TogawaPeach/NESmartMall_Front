# 商品接口

## 首页商品接口

首页默认停留在“全部”，组件挂载时自动查询销量前八的商品，加载时显示八张骨架卡片：

```http
GET http://localhost:8082/api/products?limit=8
```

开发环境由 `vite.config.ts` 将前端的 `/api` 请求代理到 `http://localhost:8082`，避免浏览器跨域。修改代理配置后需要重新启动开发服务。生产构建默认使用前端同源的 `/api/products`；部署时需配置服务器 API 反向代理，或在构建前通过 `VITE_API_BASE_URL` 指定允许跨域访问的后端地址。`VITE_PRODUCTS_ENDPOINT` 可覆盖默认路径。环境变量不可包含密钥。

## 分类与排序

前端不发送 `sort`，统一使用后端默认的销量降序排序。“全部”省略 `categoryId`，其他分类按以下固定映射发送：

| 选项卡     | categoryId |
| ---------- | ---------- |
| 全部       | 不传       |
| 全站仪     | 1          |
| GNSS / RTK | 2          |
| 水准仪     | 3          |
| 测距仪     | 4          |
| 配件       | 5          |

例如选择全站仪时发送 `GET /api/products?categoryId=1&limit=8`。参数顺序不影响请求含义。切回“全部”重新查询并省略分类参数。每次分类查询和重试均最多展示八条结果，等待响应期间显示八张骨架卡片。

前端已按此约定发送请求；后端仍需接收可选的 `categoryId`，先按分类筛选，再按销量降序取前八条。不传分类时查询全部分类；传入分类时仅返回该分类的商品。

## 返回结构

```json
{
  "code": 200,
  "message": "OK",
  "data": [
    {
      "coverUrl": "https://example.com/product.webp",
      "id": 1,
      "name": "商品名称",
      "price": 990,
      "sales": 0
    }
  ]
}
```

仅 `code: 200` 视为业务成功，商品列表读取 `data`。每个商品卡片上方显示 `coverUrl`，中间显示 `name`，底部左侧显示价格、右侧显示 `sales` 对应的购买人数。长名称最多显示两行；图片失败或缺失时显示占位。

`price` 为人民币分，接口适配层除以 100 后输出 `priceYuan`，例如 `990` 分显示 `¥9.90`。明确的零价格正常展示，缺失价格显示“价格待确认”。价格必须为非负整数分；`sales` 必须为非负安全整数，`0` 显示“0人购买”，缺失人数显示“购买人数暂无”。

## 配置与状态

- `src/api/productContract.ts`：接口路径、`categoryId` 与分类 ID 映射、`limit`、字段路径、业务成功状态及价格单位；排序使用后端默认规则。
- `src/api/products.ts`：GET 查询、响应校验、价格转换及购买人数映射，最多保留请求指定的条数。
- `src/composables/useHomeProducts.ts`：默认分类、八条查询、加载/成功/空列表/失败状态、重试及请求取消。只应用最新请求，避免旧响应覆盖新结果。
- `src/components/storefront/ProductCard.vue`：简介卡布局、价格格式和购买人数显示。

只有业务成功且 `data: []` 时显示空列表。网络失败、超时、业务失败、列表非数组、重复商品 ID、字段类型异常均显示失败提示。首页不填充演示商品。

首页商品查询不发送关键词。搜索栏独立校验输入，首页搜索在新标签页打开搜索结果，搜索结果页再次搜索则在当前页面更新；搜索使用下面的分页接口，不影响首页分类商品。

## 商品列表分页接口（后端待实现）

首页点击“查看全部商品”或“查看全部 + 分类名称”后，在新标签页打开商品列表页。该页使用独立分页接口，首页现有 `/api/products?limit=8` 请求和数组响应保持不变。

前端已按以下约定准备查询；当前后端分页实现尚未完成。默认路径为 `/api/products/page`，可通过 `VITE_PRODUCT_PAGE_ENDPOINT` 覆盖。示例请求：

```http
GET /api/products/page?pageNum=1
GET /api/products/page?categoryId=1&pageNum=2
```

`pageNum` 从 1 开始，必须为正安全整数。分类 ID 使用上述固定映射，“全部”省略 `categoryId`。分类浏览不发送关键词，搜索请求发送 `keyword` 并省略 `categoryId`。前端不发送 `pageSize`、`limit` 或 `sort`；后端固定每页最多 12 件商品，并使用默认排序。切换分类从第 1 页查询。

后端分页响应需同时返回本页商品和当前分类下的商品总数，例如：

```json
{
  "code": 200,
  "message": "OK",
  "data": {
    "list": [
      {
        "coverUrl": "https://example.com/product.webp",
        "id": 1,
        "name": "商品名称",
        "price": 990,
        "sales": 0
      }
    ],
    "total": 1,
    "pageNum": 1,
    "pageSize": 12
  }
}
```

商品字段、价格单位及 `code: 200` 成功约定与首页一致。`total` 必须是非负安全整数，表示筛选后的全部商品数量；`pageNum` 必须与请求页码一致，`pageSize` 必须为 12，`list` 长度不得超过 12，页内商品 ID 不得重复。前端不通过本页条数估算总数，也不在接口失败时填充演示数据。

后端使用 PageHelper 时，应关闭自动把越界页码调整至首尾页的行为：请求超出最后一页时，仍返回请求的 `pageNum`、实际 `total`、`pageSize: 12` 和 `list: []`。前端据此计算最后一页并重新查询。这样 URL 页码、分页组件和实际商品保持一致。

Element Plus 分页组件固定 `page-size="12"`，使用 `layout="prev, pager, next"`，不提供每页条数选择器。分页组件的 `total` 直接使用后端响应；例如当前分类有 50 件商品，共 5 页，最后一页 2 件。后端未实现、网络失败、业务失败或分页字段不符合约定时，列表页显示失败状态并允许重试。

分页相关适配入口为 `src/api/products.ts` 的 `queryProductPage({ category, pageNum, keyword? })`；固定页大小为导出的 `PRODUCT_PAGE_SIZE`。`src/api/productContract.ts` 中的 `productPageContract` 配置路径、关键词参数和分页字段映射，复用首页商品字段映射及响应校验。

## 关键词搜索（前端已实现，后端待联调）

点击搜索图标或按回车时，先去掉搜索词首尾空格。空输入或仅含空格时，在导航下方显示 Element Plus `ElAlert`，内容为“请输入搜索词”，使用 `type="warning"`、`center` 和 `show-icon`；不发送商品请求、不打开标签页，并聚焦搜索框。输入有效内容后隐藏提示。中文输入法选词的回车不触发搜索。

首页或分类浏览页提交有效输入时，在新标签页打开 `/products?keyword=RTK&page=1`。搜索结果页保留搜索栏、隐藏分类栏、显示搜索词和匹配商品总数，每页最多 12 件商品；成功且有结果时显示分页栏，包括只有一页的情况。没有结果时显示“未找到相关商品”，失败时允许重试。编辑或清空搜索框只是修改待提交内容，当前结果仍由 URL 中的搜索词决定；搜索结果页再次提交有效搜索词时，在当前标签页更新 URL 和商品结果，并回到第 1 页；同词在第 1 页重复提交也会重新请求。

```http
GET /api/products/page?keyword=RTK&pageNum=1
GET /api/products/page?keyword=RTK&pageNum=2
```

搜索覆盖全部分类，不传 `categoryId`。关键词由 Vue Router 和 Axios 分别负责页面 URL 与请求参数的编码。翻页、刷新、重试和越界页码纠正均保留已提交的关键词。加载时显示 12 张骨架卡片，旧请求不得覆盖最新结果。

本次只实现前端请求与展示，不修改后端。联调要求：后端以商品名称包含关键词进行匹配，先筛选再按销量降序、同销量按商品 ID 升序分页；返回上述分页结构，`total` 为搜索匹配的商品总数。不能用前端过滤本页商品代替后端搜索。搜索页不请求首页最多八条的接口，也不要求新增型号字段。

## 验证

```sh
npm run build
```

启动后端与 `npm run dev` 后，访问首页检查商品图片、名称、`¥9.90` 和“0人购买”。接口不足八条时只展示实际返回条数。后端完成分类筛选后，核验五个分类对应的请求参数与返回商品，切回“全部”时不传 `categoryId`，所有请求均不传 `sort`。

搜索联调：空输入、全空格输入均提示且不新增请求；有效输入后检查新标签页 URL、搜索框回显、分类栏隐藏和第一页请求。在搜索结果页改词后点击搜索或按回车，检查当前标签页更新且页码回到 1；同词重复提交应重新请求，空输入仍提示且不新增请求。检查中文及 `+`、`&` 等字符编码，翻页保留关键词，每页最多 12 件；验证单页、末页、无结果、失败重试和越界页码纠正。编辑搜索框后翻页或重试仍使用 URL 中的已提交词；首页输入搜索词后切换分类仍只请求当前分类的八条商品。


## 商品详情接口（前端已接入，后端待联调）

首页、分类列表和搜索结果中的商品卡片用新标签链接打开 `/products/{id}`，原页面保留。新页加载、刷新、直接访问、重试及登录恢复均直接调用 `GET /api/products/{id}`，不调用 `detail-entry`，不再校验入口 `productId/detailPath`。复用现有 HTTP 客户端和 Bearer token，开发环境经 Vite `/api` 代理转发至 `http://localhost:8080` gateway。响应沿用 `{ code: 200, message: "OK", data: {...} }`，仅 `code: 200` 为业务成功；`data.id` 为字符串，保留与请求 ID 的一致性检查及安全整数 number 的已有兼容，BIGINT 必须使用字符串。

详情内容 data 字段为 `id`、`name`、`model`、`coverUrl`、`price`、`sales`、`stock`、`detailImages`。`price` 为非负整数分或 null，详情页保留整数分格式化为两位小数人民币，避免大额价格分位丢失；`sales/stock` 为非负安全整数；`model` 为可空单个型号，直接展示不切换 SKU；`detailImages` 为完整 HTTP/HTTPS 图片地址数组，按顺序排列，不能返回 JSON 字符串。`coverUrl` 可 null；`coverUrl/price` 缺值时必须显式返回 null。详情图片对应数据库 `product.detail_image_urls`，不并入列表响应。

页面上部左侧头图，右侧名称、型号、价格、已售与库存，下方实心“立即购买”和描边“加入购物车”；下部按顺序展示详情图。库存为 0 或价格 null 时禁用两按钮；本期不发购物车或订单写请求，有货且价格明确时点击提示暂未开放。页面覆盖加载、空详情图、图片失败、缺货、登录、不可访问和失败重试。`detailImages: []` 是正常成功结果，商品信息继续展示，仅图片区域显示“暂无详情图片”。

HTTP 或业务 401 提示登录，登录成功自动重查；403 无权限；404 统一表示商品不存在、下架或删除，页面显示商品不可访问。移除 `DETAIL_NOT_CONFIGURED` 和入口未配置专用状态。HTTP 失败状态优先于正文业务码。切换 ID、会话变化或离开页面时取消请求，旧结果不得覆盖新页面。详情公开策略由网关控制，此次不新增白名单。

正式字段与验收要求见 [商品详情页需求](./requirements/商品详情页需求.md)。本轮仅修改前端项目，不修改后端或数据库；详情读取不再依赖路径关联表。生产部署仍需配置 SPA 路由回退。自动化验证与限制见需求文档第 12 节；真实 gateway 和后端数据联调尚未执行。
