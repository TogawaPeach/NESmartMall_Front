# 取消订单前端接入

2026-10-20：订单列表和详情共用 `OrderActions`，待付款订单经二次确认后取消，不依赖支付资格字段齐全。

## 后端接口

`POST /api/orders/{orderNo}/cancel`，空请求体，沿用统一 Bearer 鉴权，不发送用户 ID、内部订单 ID、状态或商品数量。

成功 HTTP 200：

```json
{
  "code": 200,
  "message": "OK",
  "data": {
    "orderNo": "JW2112134513910874112",
    "status": "CANCELLED"
  }
}
```

订单号必须匹配，状态必须为 `CANCELLED`，取消响应不再要求或解析 `cancelledAt`。取消时间仍由已有订单详情查询提供；取消成功后详情刷新失败时保留已取消状态，尚未取得取消时间则不展示该时间。失败沿用 code/message/data，data 为 null：400 参数错误，401 登录过期，403 无权限，404 不存在或不可见，409 已付款等不可取消状态，500 事务执行失败。后端须保证取消与库存回补共同提交或回滚、重复取消不重复回补；手动取消不要求等待 15 分钟。

## 前端行为

- 提交期间防重并阻止同一组件付款；取消弹窗关闭时不提交。
- 成功先更新当前订单事实，再刷新列表或详情；保留状态筛选。后续刷新失败保留已确认状态，显示刷新提示，不恢复支付入口。
- 409 展示后端提示并查询最新订单；已付款时更新为当前状态。
- 超时、断网或成功响应格式异常时，仅查询订单核对，不自动重发取消。查询仍失败则保留结果未知提示及查询入口，暂停付款；查询确认仍待付款后允许用户再次确认取消。
- 切换账号、订单或卸载组件会中止请求并忽略迟到响应。
- 开发模拟的取消写操作仅在显式开启订单与购物车 mock 时启用，不模拟真实库存事务。

## 验证边界

自动测试覆盖空 POST、Bearer、最小响应校验、错误状态、防重、查询恢复、会话隔离、刷新失败保留及模拟 HTTP 接口；独立虚构账号预览验证列表筛选移出、关闭确认不取消、详情取消及时间展示。

真实后端取消接口、Seata 回滚和库存回补仍须联调。使用真实创建并扣库存的订单；历史固定测试订单未扣库存，不应直接用于回补验收。
