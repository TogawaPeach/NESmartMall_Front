## 自动化覆盖

- 只打开小票无写请求；未填收货不请求；创建仅发送选中商品 productId 字符串与数量、trim 后 recipient；不发用户 ID、价格、金额、UUID 或 Idempotency-Key。
- 创建中重复点击、关闭重开和购物车所选项清空均不重新创建；成交名称、数量与金额来自服务端快照；暂不支付保留原单；创建后购物车刷新失败不推翻成功。
- 断网、超时、HTTP 500、畸形成功响应均保存未知结果，无直接重下单；组件卸载后另一消费者仍保留该事实。
- 明确 400/409 拒绝、401/403、404/405 未开放均不会假成功；严格写响应校验缺字段、message 非 OK、空明细、金额不一致、不安全金额、非法订单号、收货边界和重复商品。
- `/pay` 无业务 body；0 元需明确 paidAt/paidAmountFen=0 与已支付状态；错误订单号或畸形支付响应必须按原 orderNo GET 恢复；网络未知且 GET 失败不显示成功。
- 服务端时间与本地经过时长倒计时；恰好到期禁用付款并只查询一次，后续 tick 不轮询；订单仍 PENDING_PAYMENT，cancelledAt 仍 null，显示关闭处理中。旧 GET 缺支付字段继续解析，不授予付款资格。
- 退出/换账号清理旧状态，迟到响应隔离；旧关闭小票的迟到结果不关闭新账号确认框；Axios 拦截器执行前切账号时，旧创建/支付请求不配新 Bearer 发出；旧 orderNo 查询入口不能借新账号授权发请求。
- 现有购物车增删改、认证、客服、商品、订单查询与确认收货相关项目测试继续通过。确认收货保持 `POST /api/orders/{orderNo}`。

测试先观察了旧逻辑下缺少创建/收货/持久状态等失败，再实现通过。独立代码审查复现的发送前会话竞态经失败用例验证后修复，并跑了完整套件；未留下已知的重要问题或延期次要项。
