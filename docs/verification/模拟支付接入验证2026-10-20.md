# 模拟支付接入验证

日期：2026-10-20（Asia/Shanghai）。本轮仅实现前端及显式开发模拟，未修改后端、数据库或部署，未提交推送。

## 最终行为

- 小票创建成功弹窗新增“立即支付”，沿用后端创建返回的订单号和整数分金额。创建成功不自动付款；关闭或暂不支付保留原单。
- 弹窗与订单列表/详情共用 `payOrder` 和 `useOrderPayment`：`POST /api/orders/{orderNo}/pay`，无业务请求体，使用现有 Bearer。
- HTTP 200 且业务 `code === 200` 即支付明确成功，不解析支付响应的 data；兼容后续 `data: null` 及当前后端仍返回 detail。订单详情另行 GET。
- 支付明确成功独立保存，即使 GET 失败也不撤销成功、不允许再次支付；显示刷新错误并提供刷新入口。未知结果按原订单号查询，失败保留未知并阻止重复付款和新购买。
- 订单页不再因缺失 `canPay/serverTime` 等旧付款字段而禁用入口；打开付款弹窗后先取得详情，已有明确禁止或服务端时间到期仍阻止支付，最终资格由后端判断。
- 订单页付款初始查询不使用缓存摘要重设倒计时，防止旧 serverTime 在弹窗打开时重新起算。确认收货、创建订单请求体和购物车清理方式保持。
